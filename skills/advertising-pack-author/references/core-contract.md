# Extension Pack core contract

A pack is a reusable campaign-production grammar, not a platform adapter or user/project authority source.

## Qualification

Create a pack only when the knowledge is reusable across projects, materially changes production behaviour, would add irrelevant specialisation to core, can be demonstrated by an exact showcase and can be distinguished from core in evaluation.

## Precedence

1. verified binding Legal/standards/platform constraints and explicit project instructions;
2. approved/locked business and campaign decisions;
3. selected Advertising Extension Pack;
4. core Advertising defaults.

A pack grants no new commercial, data, rights, publication, spend or external-execution authority.

## Evidence

Each implemented catalogue pack needs a full showcase prompt, complete core-only comparator, behavioural observables, adverse challenges and actual core-versus-pack comparison. A pack survives only if specialised behaviour is useful without unacceptable regression. No superiority is assumed.

## Compatibility

Record exact compatible core/pack revisions. Composition is exceptional and must have explicit compatible scopes; do not silently merge packs or build a universal pack interpreter.
