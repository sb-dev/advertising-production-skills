The opening explains the purpose and actual availability before inviting execution. Five capability bullets group work by user intent. Quick start precedes the five-level learning catalogue; skill/pack choice and execution boundaries follow, then measurement, evidence, source-aware stress tests, owned docs, contribution and rights. Technical terms such as attribution and incrementality are preserved with their practical distinctions rather than replaced by vague marketing language.

## Publication design and later evidence-driven updates

The complete copy lives at `docs/research-logs/2026-09-10-stage-20-public-readme.md` for direct review. Links are relative to that actual location and work there. Stage 22 may adopt the copy at the root by resolving each local link against this location and rebasing it to `README.md`; changing paths must not change prose, prompts or their meaning. The verifier checks this transformation in memory and verifies equivalent targets and exact prompt preservation. No custom publishing system or root change is introduced here.

The copy is a truthful snapshot, not a permanent prohibition on later updates. Update availability only from actual new evidence: scaffold files justify their existence, an installed vertical supports its demonstrated scope, a completed example supports that example's output/evaluation link, and clean-consumer records support their exact tested host/revision. Replace the corresponding design-only wording when that evidence exists, retaining unproven areas explicitly. Do not use one completed vertical to mark all fifteen examples produced or all eight packs mature.

Each primary entry must keep its original ID, level and complete prompt. When actual production is accepted, add its real output/evaluation route alongside the prompt and identify the tested revision; do not replace the exercise with a marketing thumbnail. A pack adds actual showcase/negative/differential evidence only after all required conditions. Contributor/licence links replace their absence statements only when the actual files and terms are accepted. No unverified release, registry change or PR readiness is authorised by these update rules.
