### Evidence classes and reuse

A skill body can establish what instructions it contains. It cannot establish that a model follows them. A README can establish documented intent and interface examples, not the correctness of every referenced implementation. API documentation can describe an endpoint or entitlement, not the user's live account capability or lawful data use. A method walkthrough can explain expected analysis and data handling, not reproduce its numerical results. A product page can identify an available class of service without proving its advertised quality, latency or economics.

All fifty-four source records retain title/location, actual access scope, publication/update or other date information when established, retrieval date with honest precision, finding, limitation and repository blob where returned. Search-returned primary text is labelled as such. A direct fetch error is preserved rather than described as a completed full read. No PDF, private account, rendered advertisement, model output, live analytics report, user dataset or commercial licence agreement was analysed in Stage 11.

The current claude-ads conductor was compared using its actual returned body, not an older cached release description. Google's current catalogue is broader than the two API-engineering entries described on one developer page. Replicate's current README lists seven skills, but only run-models was read substantively. These differences prevent either over-crediting uninspected modules or rejecting a current package for an older description. [R05] [R07] [R09] [R14] [R15]

Data retention and confidentiality are not synonyms. Deleting a JSON record does not necessarily remove its input/output files. A signed or restricted output does not necessarily protect an earlier upload. An unknown ACL nickname being ignored is a reason to verify effective access, not assume the intended policy was enforced. Keep these distinctions in the selected provider contract rather than a universal string called private. [R18] [R19]

Likewise, a “read-only” interface can disclose account information to a model or expose a separate feedback action. Review actual operation and recipient scope. A generation API may alter an existing design if a particular mode is selected. A browser tool can submit, upload or use persistent credentials; isolated state and host/origin options alone do not establish complete containment. These are explicit task risks, not a reason to disable all useful execution. [R10] [R24] [R36] [R42] [R52]

Licence identification is not source incorporation. The two complete MIT texts were read; Replicate's Apache heading/initial definitions were read, but its full terms/NOTICE and dependencies were not audited. Other API terms, model licences and enterprise agreements were not comprehensively reviewed. Before a specific import or paid use, obtain the applicable current terms and preserve required notices. Do not conflate a repository licence with rights to customer data, an actor's voice, music advertising use or a generated depiction of a real product. Legal conclusions remain with the responsible Legal owner under Stage 10.

No actual quality, latency, token saving, ROAS uplift, price quote, forecast or cost benchmark is produced here. Comparing documented contract features resolves Stage 11's selection questions; model-level quality/cost choices and runtime evidence belong to their actual later scope. Future prices, quotas and availability must be checked for the chosen product and date rather than copied from a stale research table.
